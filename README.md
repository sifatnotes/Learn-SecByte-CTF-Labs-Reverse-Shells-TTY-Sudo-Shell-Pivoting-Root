- **Environment Inspection:** Understanding shell environments and configuration-related security risks.

- **Shell Relays & Pivoting:** Studying shell movement and pivot concepts in controlled environments.

- **Privilege Escalation:** Connecting shell access with Linux permission and configuration weaknesses.

## Learning Path

A practical progression through this collection is:

1. Start with **environment inspection** and shell fundamentals.
2. Learn how **TTY and `stty`** affect interactive shell behavior.
3. Practice **shell stabilization** in controlled environments.
4. Study **reverse-shell architecture** and relay concepts.
5. Explore **shell pivoting** and how access paths can lead toward higher privileges.
6. Study **sudo configuration and privilege boundaries**.
7. Finish with watchdog and red-team scenarios to connect offensive testing with defensive monitoring.

## How to Use the Labs

Use these exercises only in authorized lab environments.

Recommended workflow:

1. Read the lab objective and identify the intended security concept.
2. Perform controlled reconnaissance within the provided environment.
3. Document shell behavior, permissions, services, configurations, and security controls.
4. Investigate the challenge using only the authorized lab target.
5. Record the security impact and the conditions that enabled the issue.
6. Consider defensive mitigations such as least privilege, secure sudo rules, shell restrictions, monitoring, and proper TTY configuration.

For reverse-shell, pivoting, shell-escape, and watchdog exercises, use isolated training environments and never apply the techniques to systems without explicit authorization.
